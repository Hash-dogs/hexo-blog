八天之内，DeepSeek 与 OpenAI 相继开源 Harness：Agent 时代的"运行时"之战

hash-dog2026-08-222026-08-22

一、引子

2026 年 8 月 14 日，DeepSeek 开源了 DeepSeek Harness，简称 DSH。项目刻意用黑色鲸鱼标识，和自家模型产品的蓝色鲸鱼区分开。口号只有一句话：Everything is a Plugin，一切皆插件。

八天后的 8 月 20 日，OpenAI 发布官方博客《Codex as a platform: build on the open agent harness》，宣布把驱动 Codex App、CLI、IDE 扩展的那套底层运行时全面开源，Apache-2.0 许可。

两个 AI 领域最受关注的公司，八天内先后把各自”Agent 发动机”的核心放到了 GitHub 上。这不是巧合。

时间线再往前看，其实更热闹。月之暗面的 Kimi Code 早已开源，MIT 许可；智谱在 GLM-5.2 发布时介绍了 ZCode；Pi Harness 也一直以 MIT 许可低调存在。但 DeepSeek 和 OpenAI 的这波操作，把”Agent 运行时”这个词一夜之间顶到了台前。

这篇文章想聊三件事：他们到底开源了什么？为什么扎堆开源？这波连锁反应会把 AI 竞争带向哪里？

二、Harness 是什么：为什么巨头开始”交底”

先把概念讲清楚。DeepSeek 和 OpenAI 用的公式是同一个：

Agent = Model + Harness

模型负责”思考”，也就是推理、生成、理解任务；Harness 负责”干活”，读取文件、调用工具、管理上下文、做任务规划、执行命令、验证结果。一句话：模型提供潜在能力，Harness 决定交付能力。

这个道理其实不新鲜。上个月我写《从 FDE 到 OPC》时聊过 Harness Engineering，当时它还只是北京政策公文里的一个术语，很多人觉得是学术黑话。一个月不到，DeepSeek 和 OpenAI 就用实际行动证明了这不是黑话，而是真金白银的主战场。

这个领域还有一个被反复引用的量化证据。OpenAI 官方博客披露：在 ARC-AGI-3 基准上，仅做两处 Harness 层面的调整，保留推理和上下文压缩，GPT-5.6 Sol 的得分就从 13.3% 跃升到 38.3%，输出 Token 减少到原来的约六分之一。

单独运行 13.3%，套上 Harness 38.3%。这不是换了个模型，只是优化了模型外面那层”壳”。模型没变，外面那层壳变了，效果几乎翻了三倍。谁掌握了那层壳的规则，谁就掌握了 Agent 能力的上限。

所以当 DeepSeek 和 OpenAI 先后把壳开源，行业的第一反应是：这背后有大事。

三、DeepSeek Harness：一切皆插件，Agent 界的安卓

DSH 的核心设计只有一条：没有任何特权内核。

模型适配器、工具注册表、Skills、会话日志、沙箱、存储、调度、UI，甚至 Agent 主循环本身，全部都是可插拔的插件。官方文档的原话是”没有需要打补丁的特权内核”，扩展 Harness 的方式是挂新插件，而不是 fork 源码。

这套机制底层由 Cordis 这个元框架驱动，DeepSeek 与北京大学联合研发，论文叫《A Programming Paradigm for Spatiotemporal Composability》。Cordis 不是从零开始：它已经在 Koishi 框架上运行了四年，经过 4000+ 社区插件的验证。所以 DSH 的”一切皆插件”不是 PPT 概念，背后有一套跑了四年的成熟内核托底。

图：DeepSeek Harness 将运行能力组织成插件，开发者可以查看、替换和重新组合不同组件（来源：腾讯科技报道）

几个让我印象深刻的细节。

第一，它刻意不绑定自家模型。 DSH 支持 OpenAI、Anthropic、AWS Bedrock、Azure、Gemini 以及所有 OpenAI 兼容端点。DeepSeek 不仅不强迫你用它家的 V4，甚至允许你把 Claude Code 和 Codex 装成它的子代理，RC.8 版本直接支持按需安装。开源最彻底的姿态，莫过于主动为竞争对手留入口。

第二，它给了”自进化”的想象空间。 四种预设模式里，创造模式允许 Agent 动态挂载、卸载插件。理论上，一个 Agent 可以自己给自己装新能力。再加上 Trajectory 轨迹视图，记录模型看到的所有内容，支持断点复原、重放、分支派生，DSH 把”可观测、可演进”做到了产品层。

第三，社区反应是现象级的。 发布时间线大概是这样的：

时间点 Star 数量
发布首日 破 3 万
12 小时内 破 5 万
第 5 天 14.9 万
8 月 20 日，开源第 6 天 约 17.37 万，Fork 1.88 万
现在，8 月 22 日 约 18.2 万

到 8 月 20 日，社区已经积累了 5100+ 插件、3500+ 作者。五天时间，社区补上了官方没来得及做的桌面应用（甚至有压到 18MB 的版本）、读图插件、IDE 形态、TUI，以及从 Claude Code、Cursor 迁移的工具。DeepSeek 官方还放出了自家工程团队每天在用的十几个 Skill。

连竞品 Pi 的掌舵者、Flask 之父 Armin Ronacher 都公开表态：”这确实是我头一回看到这个领域里的新东西，被触动到想重新审视我们自己的一些选择。”

四、OpenAI Codex Harness：工业工程主义，一台调教好的 iOS

如果说 DSH 是让开发者自己攒发动机，Codex Harness 就是一台发动机已经被调教到极致的成品车。

Codex Harness 本质上是 Codex App、CLI、IDE 扩展共用的同一套底层运行时，负责管理会话状态、长对话记忆、工具调用、流式执行、错误恢复、沙箱约束、权限边界和人工审批。控制平面与计算平面分离：Harness 只负责逻辑调度、审批拦截和记忆决策，不直接执行代码。所有真实的文件读写、编译和命令执行都下沉到独立沙盒，macOS Seatbelt、Linux Landlock、Windows AppContainer，并集成 Temporal.io 持久化引擎与 SQLite 状态机。

它开源的方式也很有”平台感”，不是扔出一个仓库让你自己折腾，而是给你三个按集成深度递增的入口：

组件 定位 适用场景
codex exec CLI 自动化 脚本、CI 作业、一次性后台任务，运行”有边界的 agent 工作流”，返回结构化输出
Codex SDK，TS/Python 编程式接口 在应用代码里精确控制 Thread、Turn 生命周期，启动、恢复、流式传输任务
codex app-server 产品级引擎 JSON-RPC 连接本地 Codex 进程，支持跨轮次会话、实时事件流、中断、挂载应用自有 MCP 工具、人工审批

官方博客反复强调一句话：不要做一个换皮聊天框。真正的差异化机会是围绕具体岗位的既有工作方式构建软件，比如安全分析师的调查队列、支持工程师的客户历史与日志、产品团队的任务看板。界面本身是体验的一部分：它告诉 Agent 用户在看什么，给它合适的工具，也给用户一个审查下一步的地方。

这套设计不是纸上谈兵，官方给出了真实部署案例：

  • Cisco：在 Cisco Cloud Control 的 App Builder 里用 Codex SDK，让客户用自然语言创建云应用；
  • 税务工作流，Thrive Holdings 与 Crete：试点处理了约 7000 份纳税申报表，准备时间缩短约三分之一；
  • GitHub 与 JetBrains：把 Codex 带入现有 IDE 工作流；
  • Relay：官方示例运营应用，货运异常仪表板旁嵌入 Agent，用应用自有的 MCP 工具取数，重新预订货运等写操作须经人工审批。

图：OpenAI 展示的物流运营场景，Codex 被嵌入业务控制台，辅助调查异常运单（来源：腾讯科技报道）

值得注意的边界：开源的是 Harness 和集成层，模型访问、账号额度、托管服务仍然是独立的付费层。开源不等于免费模型。另外，IDE 扩展和 Codex Cloud 并不在开源范围内。

同样是 Model + Harness，DeepSeek 和 OpenAI 给出了两种截然不同的答案。业界有个很贴切的类比：

DeepSeek 想做安卓，OpenAI 想做 iOS。

维度 DeepSeek Harness OpenAI Codex Harness
设计哲学 理论驱动，解构特权内核 场景驱动，工业工程主义
开放程度 彻底开放，连”发动机”都能自己组装 核心调教好，接入非核心组件需适配
技术底座 Cordis 元框架 + Node.js Rust 核心，codex-rs + TypeScript SDK
模型绑定 刻意不绑定，甚至支持对手模型作子代理 面向 Codex、ChatGPT 生态
类比 安卓，洞洞板，什么都能插拔 iOS，精装房，产品化集成
优势 高可扩展、模型可换、审计追踪完善 真实产品验证充分、三层接入门槛低
代价 需自行建设 UI、权限、监控、多租户 扩展自由度相对受限

五、底层架构对决：谁的骨架更硬？

前面的对比还是表面功夫。这一节把两个 Harness 拆开，看各自的底层骨架，这是判断一个运行时到底是不是真开放的关键。

DeepSeek 的骨架：无特权内核 + 一切皆插件

DSH 最硬的一条架构原则是：**系统里不存在”特权内核”**。模型适配器、工具注册表、Skills、会话日志、沙箱、存储、调度、UI，甚至 Agent 主循环本身，全部是平级的插件，通过统一的 Cordis 机制管理，支持热卸载、回滚和依赖管理。

这意味着两件事。

第一，替换底层组件不需要维护分叉源码。 传统插件系统里，”插件”只是挂在外壳上的扩展点，核心还是你动不了的。DSH 连核心都是插件，替换 Session、存储、沙箱甚至 Agent Loop 时走的是同一套机制，不需要长期维护一份和上游分叉的源码。

第二，系统唯一咬死的是日志。 极客公园那篇报道点得很准：DSH 唯一不可替换的东西是”模型看过什么必须记下什么”，任何进入模型请求的内容，都要能从日志重建。这是整套”一切皆插件”能成立的基石。因为所有东西都可替换，所以必须有一个不可动摇的审计基线来兜底。

优点非常明显：可组合性拉满、模型可随时切换、审计追踪完善、社区生态爆发力极强。

代价也很实在：UI、权限、监控、多租户这些平台能力，都要开发者自己建。而且沙箱目前主要约束文件系统，不是一个完整的安全边界。DSH 给出的是一套”骨架”，血肉要社区来长。

Codex 的骨架：控制/计算分离 + 生产级状态机

Codex Harness 的架构哲学和 DSH 完全相反：控制平面与计算平面分离。

Harness 本身只负责逻辑调度、审批拦截和记忆决策，不直接执行任何代码。所有真实的文件读写、编译、命令执行，全部下沉到独立沙盒，macOS Seatbelt、Linux Landlock、Windows AppContainer，再配合 Temporal.io 持久化引擎和 SQLite 状态机管理任务生命周期。

这套设计的好处是工程上极其稳健：

  • 沙盒是系统级的，安全边界比”约束文件系统”硬得多；
  • Temporal.io 让长任务可持久化、可恢复，Agent 跑了半小时被打断，状态不丢；
  • 三层入口，exec → SDK → app-server，开箱即用，产品团队接入门槛低。

代价是：核心被”调教好”了，你轻易碰不到发动机。扩展自由度相对受限，接入非核心组件需要和这个核心适配。

那么，谁更完善？

把两套骨架摊开，我的看法很明确。

在架构理念上，DeepSeek Harness 更”完整”。 它把”无特权内核”贯彻到了极致，连 Agent Loop 都可以替换。Codex 的”控制/计算分离”在工程上更稳健，但本质上仍是”一个调教好的特权核心 + 外部沙盒”的模式，核心是闭源保护起来的。DSH 的 Cordis 统一插件机制，让”替换底层组件”这件事有了统一解法，这是它真正领先的地方。

但一个 Harness 能不能成为行业标准，比的不是理念，是工程。 在下面这几个维度，DSH 需要向 Codex 学习：

学习点 DeepSeek Harness，现状 OpenAI Codex Harness，标杆
工程化验证 开发者预览版，破坏性变更频发，RC.8 SQLite 数据结构不兼容 经 Codex App、CLI、IDE、Web 多年真实产品验证
安全边界 沙箱主要约束文件系统，非完整安全边界 控制/计算分离 + 系统级沙盒，Seatbelt/Landlock/AppContainer
任务稳定性 起步阶段 Temporal.io 持久化 + SQLite 状态机，长任务可恢复
产品化集成 需自行建设 UI、权限、监控、多租户 三层入口开箱即用，企业可直接嵌入

一句话总结：DSH 是”骨架全、血肉少”，Codex 是”血肉全、骨架封闭”。 谁能在保持自己优势的同时补齐对方的短板，谁就可能成为 Agent 时代默认的运行时。这场对决才刚开始，真正的答案还没出来。

六、一场”运行时”暗战：为什么巨头扎堆开源？

问题来了：费了那么大劲建起来的护城河，为什么要主动拆开？

我从报道里读出了至少三层逻辑。

第一层：数据闭环。

这是最直接、也最本质的动机。模型公司过去只提供 API 时，任务跑在 Claude Code、Codex 等外部 Harness 里，”能看到模型请求，很难完整理解请求之前发生了什么，以及模型输出之后任务有没有真正完成”。开源 Harness 后，模型公司能观察用户在什么任务上失败、工具调用卡在哪里、一次任务重试多少次。

这套数据能反过来指导模型本身的迭代。换句话说：开源 Harness 不是慈善，是给模型训练装了一双眼睛。 ARC-AGI-3 那个”Harness 一改，效果翻三倍”的数据，恰恰证明了 Harness 里的行为数据对提升模型质量有多值钱。

第二层：流量与计费。

DSH 不直接收费，但它能帮 DeepSeek 更准确地计算 Session 轮数、缓存命中率、无效重试消耗。有分析猜测，未来计费方式可能从”API Token 单价”转向”每五小时额度、任务数量、并发”这类更接近 Agent 时代的模式。

更关键的是互补品逻辑：Harness 是模型的互补品。Harness 压低 Agent 开发成本，市场 Agent 总量就增加，底层模型调用需求随之上升。Agent 任务会触发多轮模型调用，即使 DeepSeek 只拿一部分份额，绝对收入依然可能增长。DeepSeek V4-Pro 上线后大幅涨价，输出 Token 高峰价涨幅约 355%，同时开源 Harness。这就是把分发和变现拆成了两步：先免费送出工具，再在模型调用上把钱赚回来。

第三层：生态与定义权。

这是最长远、也最险的一步棋。钛媒体那篇《DeepSeek Harness 背后，梁文锋的野心》点得很透：

“一群愿意沿着你的规则做产品、做生意的人，才是 Harness 这笔账里最贵的一部分。”

开源 Harness 相当于主动放出一部分产品定义权。安卓当年也是这样，Google 把底层系统送给手机厂商，三星、小米沿此做出差异化产品，但最终都长在安卓的接口和运行方式上。今天的格局是 DeepSeek 主动兼容 OpenAI、Anthropic、Codex。如果未来越来越多公司反过来兼容 Harness 的接口和运行方式，事情就会发生质变。 谁能让更多工作流长期运行在自己的接口上，谁就更接近”模型分发和企业软件之间的控制层”。

也有冷静的声音。有开发者直言：”Codex 好在光速前进……DSH 短时间内很难超越。Harness 离开模型能力，其实是没意义的。“还有开发者给 DeepSeek 提建议：”除了交互流程优化，其他方向碰都不要碰 Harness。”理由是模型快速变化下，Harness 很难形成长期稳定的最优方案。

模型能力仍是根本，Harness 是放大器。但正因为是放大器，围绕它建立的标准、生态和习惯，反而可能比模型本身更持久。

七、未来推演：谁在定义 Agent 的规则

站在 8 月 22 日往回看，这场连锁反应的轮廓已经比较清晰了。往前的推演，我有几个判断。

判断一：Agent 竞争的主战场，从模型层上移到了运行时层。

2023 年卷参数规模，2024 年卷上下文窗口，2025 年卷 Agent 框架。2026 年 8 月这个时间点，头部公司不约而同开始交底自己的 Harness，竞争已经不再是谁的模型聪明，而是谁的”壳”能让模型稳定地完成一件真事。这是一个结构性转移，不是短期热点。

判断二：Harness 正在从护城河变成”管道”。

极客公园那篇报道的观察很精准：Harness 这一层正在从各家的护城河逐渐”管道化”，谁的模型在里面跑，变成了配置文件里的一行。DSH 允许你把 Codex 装成子代理，社区也有插件反向让 DSH 把活派给 Codex 和 Claude。当模型变成可替换组件，真正的锁定效应发生在插件、Skills、工作流这些沉淀在 Harness 上的资产上。底层模型可换，运行体系保留，这才是更高层次的生态黏性。

判断三：开源节奏不会停在 DeepSeek 和 OpenAI。

Kimi Code、ZCode、Pi Harness 都在同一条赛道上。但接下来值得关注的不是”还有谁开源”，而是”开源到什么深度”。ZCode 就不开放核心运行时源码，只开放插件、Skill 和 MCP 扩展。开放深度会成为新的竞争维度：谁能开源得更彻底，谁就能吸引更多开发者把工作流托管在自己的接口上。

判断四：模型公司会越来越像”基础设施公司”。

当 Harness 成为行业公共底座，模型公司的收入结构会从”卖 Token”转向更复杂的形态，额度、任务、并发、托管服务。而整个 Agent 生态的繁荣，会反过来扩大底层模型的总需求。DeepSeek 那句”一切皆插件”，换成大白话就是：让所有人都在我这块积木上搭房子，我就赢了。

八、所以，这一连串开源到底意味着什么？

回到开头的问题：DeepSeek 和 OpenAI 为什么要在八天内先后开源 Harness？

答案其实贯穿了整篇文章：为了数据、为了分发、为了定义规则。 三件事指向同一个方向，在 Agent 时代，掌握”运行时”的人，掌握未来十年 AI 的分发入口。

有意思的是，DeepSeek 和 OpenAI 用完全相反的路线回答了同一个问题。DeepSeek 把最该攥在手里的那一层拆开摊平公开，”让所有人踩上去，甚至包括对手”，做一个 Agent 界的安卓；OpenAI 把调教好的发动机公开成平台，让你在它的规则里做产品，做一个 Agent 界的 iOS。

两条路线没有高下之分，但有一点是确定的：模型还在卷，但风向已经变了。 从”谁的模型更聪明”，到”谁让 Agent 更可靠地干活”，再到”谁定义 Agent 的运行规则”，这串连锁开源事件，是 AI 产业上半场结束、下半场开场的哨声。

真正的比赛，刚刚开始。
